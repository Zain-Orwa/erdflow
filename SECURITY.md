# Security Policy

## Reporting a vulnerability

Please report security problems privately, not in public.

- **Do not** put exploit details, credentials, private database contents, or
  sensitive `.erdx` project data in a public issue.
- **Use GitHub's private vulnerability reporting when it is available**: open
  the repository's **Security** tab and choose **Report a vulnerability**.
- **If private reporting is not available**, open a minimal public issue
  asking for a private contact channel. Do not include any details of the
  vulnerability in that issue.

## What to include

Once a private channel is established, please share:

- the affected version or commit;
- the platform (operating system and architecture);
- the impact, as you understand it;
- information needed to reproduce the problem;
- any proof of concept, through the private channel only.

## Supported versions

ERDFlow is under active development. It does not currently maintain multiple
supported release branches; fixes are made on `main` unless the project later
declares supported releases.

Reports are handled on a best-effort basis, without a guaranteed response time.
